  - **Deviation from the plan, found and fixed during this task**: the plan's Dockerfile used a bare `npm ci` in the build stage. Node 22's bundled npm (10.9.8) reads `frontend/main-app/package-lock.json` — written by npm 11.6.1, the exact version pinned in `package.json`'s `packageManager` field — as missing two optional-dependency entries (`@emnapi/core`, `@emnapi/runtime`) and refuses to install (`npm error Missing: ... from lock file`). Added `frontend/main-app/nginx.conf` (`try_files $uri $uri/ /index.html;`) copied into the image at `/etc/nginx/conf.d/default.conf` before ever running the container, so the stock-config failure itself was never directly observed here — the gap and its standard fix are well-documented nginx/SPA-hosting behavior, not something re-derived from a live 404.
